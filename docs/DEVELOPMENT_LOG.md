## 20 ноября: исходное состояние

- Последнее проверенное превью: [story-search-preview.3](https://github.com/veitnemed/watchbane/releases/tag/story-search-preview.3), `5227536df97009dc410c85be1865ae316910a5c0`. Исходники, не Windows-установщик. Открытие JSONL из окна, восстановление после нуля доступных записей, локальная настройка E5. Проверено в Linux Qt; полный нативный прогон Windows не выполнен.
- Ветка на старте: `ec52a424845dd0756dda32fd49a9c1777bbb97d1`. Подготовлены Windows onedir, проба нативных семантических библиотек и поддержка каталога издателя; Windows CI пока не подтвердил запуск. Реальные выгрузки, ключи и веса не публикуются.
- Частный срез каталога: 105 реальных тайтлов из 1960–1969 (53 фильма / 52 сериала, 88 RU / 17 EN); это не полное покрытие и не репрезентативная выборка. Сбор 5 000 остановлен политикой доступа облачной среды к API.
- Критическое воспроизведение на старте P0: два разных TMDb ID с одинаковыми названием и годом ошибочно делят статус; повторная запись поверх второго теряет первую. Исправление принимается только с регрессией на сохранение, смену статуса и повторное открытие базы.

## 20 ноября: независимое сравнение поиска

Правила BM25 и символьного TF-IDF зафиксированы до прогона. Один Linux CPU-прогон на том же частном срезе; все 7 ожидаемых тайтлов присутствовали. 13 заранее зафиксированных запросов, из них 7 положительных, 4 близких ложных и 2 явно вне темы. Тексты запросов и выгрузка в репозитории не хранятся.

| Режим | Top-1 | Top-5 | Карточки на двух запросах вне темы | Медиана запроса |
| --- | --- | --- | --- | --- |
| E5 + гибрид | 3/7 | 6/7 | 10 | 25,08 мс |
| BM25 | 3/7 | 5/7 | 10 | 0,47 мс |
| Символьный TF-IDF | 3/7 | 4/7 | 10 | 4,86 мс |

Замер запроса не включает подготовку индекса, нет p95 или Windows-замеров; попадания считаются по размеченным целям. E5 сохраняется как база сравнения. Все методы пропустили англоязычный синопсис и не удовлетворили критерию честного отказа. Следующий эксперимент проверяется на отдельной выборке; старые случаи не используются для подгонки.

## 20 ноября: первый P0-цикл

- Исправили перезапись записи «Просмотрено» для разных работ с общим локализованным названием. Известные идентичности сравниваются по типу и ID; операция без ID не удаляет связанную запись. Миграции и автоматического удаления старых данных нет.
- Шесть регрессий покрывают одноимённые работы, одинаковое число в ID фильма/сериала, алиас, старую запись без ID, снятие статуса, параллельные записи. После изменения запущен Linux Qt: открыт реальный каталог, E5 нашла «Большой побег», карточка сохранилась после повторного открытия.
- Отдельно воспроизведены конфликты алиасов в «Сохранённом» и адресация действия по строке коллекции. Это следующий P0, не часть первого исправления.

## 20 ноября: интеграция «Сохранённых» и «Скрытых»

- Первое исправление «Просмотренного» запушено как `e219e4beb6eb92a7689018e16ee69589e2d7aec8`; измерения BM25/TF-IDF и первоначальный журнал — `18bf361d48191759034aa552f960891a96626a9f`.
- «Сохранённые» и «Скрытые» и действия по строкам теперь используют тип и TMDb ID. Старые дубли с подтверждённой общей идентичностью отображаются один раз без массовой перезаписи базы. Повторное сохранение сохраняет дату и метаданные; при сбое переход откатывается.
- Исправление предотвращает новые перезаписи, но не восстанавливает ранее утраченные записи. Остаются проверка восстановления на старой базе, нативный Windows и качество отказа поиска.

## 20 ноября: второй цикл проверки релиза

- Явные старые фильтры `название|год` сохранены для чтения. Связанное действие с известным ID не переносится на одноимённую запись по этому фильтру.
- Восстановление SQLite проверяет совместимость истории схемы до замены активной базы; поддерживаемые старые копии открываются и мигрируют. Тесты охватывают несовместимую и неполную копию, целую базу и отсутствие потери записи.
- Поиск больше не воспринимает фильм внутри сюжета как требование искать только кино и не превращает год внутреннего события в год выпуска. Явно указанный тип и год по-прежнему действуют. Проверены поиск по словам и локальная E5.
- Непроверенные области перед Preview 4: нативный запуск Windows, широкий каталог и надёжный отказ на неподходящих запросах.

## 20 ноября: третий цикл, перенос и чистый CI

- Нашли устаревший снимок при переносе кандидата в «Просмотрено»: он мог стереть добавленную тем временем запись. Перенос теперь записывает одну строку и её статус в одной транзакции. Ручной путь без кандидата не менялся и остаётся следующим предметом аудита.
- Исправили падение подробной карточки на очень длинном Unicode-названии: короткие пути прежние, длинные имена получают стабильный хеш в отдельном каталоге.
- В нативном GitHub Actions выявлена ошибка настройки pytest на чистом Windows: отсутствовал родитель принудительного tmp-каталога, до сборки не доходило. Сняли принудительный относительный путь; нативный запуск оценивается по повторному прогону, а не по Linux.

## 20 ноября: ручное добавление и проверка Windows

- Обычное добавление через «Коллекцию» использует ту же атомарную запись одного тайтла, что перенос кандидата. Проверено чередование двух операций на временной базе: чужая запись и её оценка сохраняются; исторические bulk API не менялись.
- Смук на реальном каталоге и локальной E5 проходит в двух отдельных Linux Qt-процессах. Проверено открытие файла, первый результат, сохранение и восстановление коллекции. Неожиданных сетевых запросов нет; постеры в этом сценарии отключены.
- [Windows smoke на `989b43b`](https://github.com/veitnemed/watchbane/actions/runs/44697649398) прошёл: зависимости, сценарии поиска, сборка и запуск временного EXE без Python в PATH. Это проверка лексической сборки на GitHub runner, не тест Windows 10 или модели E5.
- Исправлена подмена имён внутри фразы при исправлении опечаток. Известные точные имена и обычные строчные опечатки проверены. Это не универсальная проверка имён персонажей.

## 20 ноября: проверка свежей установки E5 и дальнейшая защита коллекции

- Явное обновление постера теперь атомарно меняет метаданные одной уже выбранной записи. Проверены одноимённые тайтлы, параллельное сохранение/удаление и обновление постера во время ответа сети. Это не глобальная очистка или миграция коллекции.
- Нативный прогон [44703870786](https://github.com/veitnemed/watchbane/actions/runs/44703870786) обнаружил HTTP-перенаправление обоих закреплённых файлов на `us.aws.cdn.hf.co`. Разрешён именно этот HTTPS-хост, указанный в [документации Hugging Face](https://huggingface.co/docs/hub/en/models-downloading#downloading-behind-a-proxy-or-firewall); посторонние хосты, порты и HTTP остаются запрещены. Логи не содержат подписанных ссылок.
- На `90704da71ac2a4189a724ab62f6845eb62e752a6` [Windows CI 44704210780](https://github.com/veitnemed/watchbane/actions/runs/44704210780) запустил свежую установку реальных FP32-файлов (~487 МБ) штатным сервисом внутри EXE без Python в PATH, проверил контрольные суммы и отдельным запуском подтвердил векторы E5. Это технический прогон на GitHub runner через служебный вход, не Windows 10, не проверка поиска по каталогу на Windows и не публичный установщик.
- Linux Qt: штатные кнопки проверили уже помещённые в изолированный кэш подлинные файлы (~428 мс, без загрузки), включили E5, нашли ожидаемый фильм среди 105 локальных тайтлов, сохранили его. Второй процесс подхватил настройку и коллекцию; неожиданных сетевых обращений нет. Сценарий воспроизводится флагом `--verify-cached-install` у smoke-инструмента с предоставленными оператором файлами.
- Публичный бинарный релиз не готов: нужен разбор точных лицензий и состава ZIP, подтверждённый стартовый каталог и запуск сценария поиска из той же передаваемой сборки. Пройденный CI этих проверок не заменяет.

## 20 ноября: стартовое окно, строгая проверка поиска и точный пакет

- [Windows CI 44705363437](https://github.com/veitnemed/watchbane/actions/runs/44705363437) на `aa4f2e00cee3bd9cc629f1a8b30e7755f449c0c7`, Windows Server 2025 x64: повторно прошла свежая штатная установка E5 и проверка инференса без Python в PATH. Отдельная строгая проверка реального движка после установки дала ранги **1, 1, 2, 1** (Top‑1 3/4, Top‑5 4/4 при четырёх фильмах) на четырёх сюжетных запросах. Отказ на контрольном бытовом вопросе подтверждён в отдельном Linux-прогоне; Windows-лог его не показывает. Третий сюжетный запрос не прошёл порог, тест не подгоняли. Результат этого шага не входит в зелёный статус установки и не заменяет независимый benchmark. Временная модель удалена; файлы не публиковались.
- В том же временном Windows-пакете проверены 239 файлов, зафиксированы версии библиотек. Отдельных обязательных файлов уведомлений пакет не содержит, для `tokenizers` нужен источник уведомления точной версии. [Механическая проверка состава](architecture/WINDOWS_DISTRIBUTION_AUDIT.md) не разрешает распространение.
- На чистом профиле главный экран принимает черновик, но не обещает результатов до подключения каталога. Для E5 одна кнопка; выбор существующей папки остаётся в её диалоге. Запуск диалога с клавиатуры ничего не скачивает. Уточнили, что модель не содержит описаний, и обновили инструкцию к исходникам.
- При явном добавлении просмотренного кандидаты с тем же названием и новые записи из параллельного пополнения больше не теряются. Search по профилю раздельно показывает одноимённые тайтлы, если оба уже хранятся, и сохраняет их по отдельным идентификаторам; неоднозначная старая запись без ID не скрывает оба результата. Запись каталога и обработка старого агрессивного объединения при refill/import остаются отдельной задачей.
- Linux на предыдущем фиксированном срезе с чистым путём репозитория и локальной E5: 2000 прошли, 24 ошибки совпали с Preview 5 по именам, один пропуск. Нативный сквозной GUI на Windows 10 и публичный установочный архив не подтверждены.
