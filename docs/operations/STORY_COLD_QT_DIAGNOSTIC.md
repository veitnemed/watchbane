# Диагностика пауз первого поиска E5

Используется только для локального QA. Пробник запускает обычный Qt StoryWorker в отдельном чистом профиле, с закреплённой FP32 E5 и одобренным оператором JSONL. Не скачивает модель и не читает рабочую коллекцию. Артефакты и исходные описания не прикладываются к отчёту; для сверки остаются только хеши.

```sh
QT_QPA_PLATFORM=offscreen timeout 90s python -m tools.qa.benchmark_story_qt_cold \
  --catalog /path/to/approved-local-catalog.jsonl \
  --model-dir /path/to/verified-e5 \
  --query 'тестовое описание сюжета без личных данных'
```

Запускайте каждый замер в новом процессе с системным лимитом времени. На Windows используйте лимит внешнего runner и указывайте фактическую редакцию системы. Два прогона сравнимы только при том же хеше каталога, модели и запросе. При сравнении вариантов укажите версию ORT, ОС, архитектуру, число доступных CPU и порядок прогонов. Не выдавайте кэш ОС за очищенный.

Измеряются промежутки между **Python-обработчиками таймера Qt** с периодом 16 мс, включая начало и конец. Паузы больше 75 мс перечисляются с пересечением фаз проверки файлов, создания сессии ORT, чтения токенизатора и кодирования. Импорт зависимостей до старта worker не измеряется. Это диагностический сигнал, а не доказательство, что нативная отрисовка или ввод зависали. Проверяйте действия пользователя в запущенном приложении отдельно. Если фазы пересекаются, их длительности нельзя складывать.

20 ноября 2026: Linux offscreen, ORT 1.23.2, 50 ранее проверенных локальных реальных описаний, три новых процесса. Порядок результата совпал, сетевых обращений не было. p95 доставки таймера около 16 мс, максимумы 0,71–1,84 с. Длинные интервалы перекрыли создание ORT-сессии и загрузку токенизатора, а не кодирование описаний. По этому замеру настройки модели не меняются.
