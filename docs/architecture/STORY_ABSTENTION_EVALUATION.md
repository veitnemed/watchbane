# Следующий эксперимент: когда не показывать карточки

## Граница задачи

В замороженной независимой оценке v2 гибрид дал выдачу на 6 из 6
посторонних запросов. Удалять карточки по одному общему порогу пока
нельзя: схожий низкий результат может быть у корректного описания,
редкого тайтла, нескольких разных сюжетов и постороннего вопроса.
Отклонение должно объяснять, что именно известно, а не делать вид, что
фильма или сериала вовсе не существует.

Уметь отличить сюжетный запрос от бытовой инструкции и уметь оценить
доказательства в **доступном каталоге** — разные задачи. Возможные
действия: показать результаты как предположения, попросить одну
конкретную деталь, сообщить об отсутствии уверенного совпадения или
пояснить назначение поиска для явно несюжетного запроса. Нельзя считать
исчезновение карточек достаточным критерием правильности.

## Пилот, отдельный от v1/v2

- Нужны локально доступные тайтлы с подтверждённым источником. Имеющийся
  срез 105 тайтлов ограничен 1960-ми и использовался для независимых
  оценок. Отдельный 50-тайтловый снимок не пересекается по ID, но не имеет
  новой разметки и полных дат. Он годится только для маленького пилота.
- Не использовать v1, v2, четыре нативных QA-текста и прежние
  экспериментальные примеры для выбора признаков или порога.
- Если достаточно материала, заранее зафиксировать 30 примеров для
  разработки и 30 для валидации; отдельно собрать неизменяемый каталог.
  В каждой половине: 10 ясных сюжетов (в том числе с опечатками и
  вопросительной формой), 10 явных бытовых задач, 5 неоднозначных
  примеров и 5 настоящих сюжетов, которых нет в этом каталоге. Исключить
  пересечение тайтлов и семейств формулировок между половинами; заранее
  записать допустимое действие и основание, зафиксировать SHA-256.
- На замороженной валидации сравнить с неизменённым гибридом при одном
  индексе. Не ухудшать корректные Top-1/Top-5 и не скрывать уже правильно
  найденные ясные сюжеты. Требовать не менее пяти исправленных ложных
  маршрутов из десяти бытовых без добавления новых. Отдельно оценивать
  пропуски корректных и неоднозначных сюжетов, сценарии без покрытия,
  обоснованность подсказки, p50/p95 и время холодного индекса.
- Ноль ошибок из десяти ещё допускает около 31% истинной ошибки по
  верхней границе двустороннего точного 95%-интервала. Пилот не является
  основанием включать пороги всем. Если не хватает независимо
  размеченных примеров и подтверждённых разнородных описаний, оставить
  текущий режим и не выдавать прототип за исправление.

Публикуются агрегаты, версии и способ измерения; операторские запросы,
каталоги и описания не прикладываются к релизу.

## Пилот 20 ноября: решение

Два автора независимо зафиксировали по 30 запросов до запуска модели.
Положительные цели разделены по чётным/нечётным позициям сортировки
строковых typed ID; пересечение целевых/неоднозначных ID между половинами
нулевое. Обе половины использовали один неизменённый срез из 50 реальных
описаний (23 фильма / 27 сериалов), без годов и подтверждённой
структурированной локали. Это проверка на подобранных вручную запросах,
не оценка всего каталога. Опубликованы только агрегаты.

| E5 FP32, Linux CPU | Разработка | Закрытая проверка |
| --- | ---: | ---: |
| Ясный сюжет: Top-1 / Top-5 | 10/10, 10/10 | 9/10, 9/10 |
| Посторонний запрос с карточками | 9/10 | 10/10 |
| Сюжет за пределами каталога с карточками | 5/5 | 5/5 |
| Неоднозначный запрос с карточками | 3/5 | 3/5 |
| Базовый словарный поиск: Top-1 / Top-5 | 4/10, 4/10 | 5/10, 5/10 |

Частный прототип фильтра прямых инструкций правил только на
разработческой половине. Первый черновик скрывал один правильный сюжет.
Зафиксированный вариант перестал его скрывать и подавил 5 лишних
выдач на разработке. На независимой половине он подавил **4 из 10**
посторонних, не потеряв уже найденные ясные сюжеты. Требовалось не
менее пяти. Подсказки и объяснения отдельно не прошли ручную приёмку,
поэтому фильтр **не включён**. Для нового варианта нужен новый независимый
контрольный набор; не править прошедшую проверку задним числом.

Проверка использовала уже доступную модель, по одному проходу на
половину: холодное построение индекса 10,13–10,56 с, p50 запросов
43–57 мс, p95 по ближайшему рангу 243–341 мс. Эти цифры не заменяют
замеры при обычном старте или на больших каталогах.

## 22 ноября: независимый классификатор намерения, без изменения выдачи

В [3e74682](https://github.com/veitnemed/watchbane/commit/3e7468232d4e2fd5f5afbcbb47ae9634d9b68318) добавлена исключительно офлайн-оценка. Модель смотрит на формулировку запроса, а не на близость фильма или сигналы ранжирования: словарный униграммный и символьный TF-IDF (3–5 символов), логистическая регрессия. Точные названия и запросы целиком в кавычках защищены. Конечное поведение моделировалось как снятие карточек, которые старый поиск показал бы; в работающем приложении карточки и подсказки не менялись.

Один автор зафиксировал синтетические 160 обучающих и 80 калибровочных запросов. Независимый автор подготовил закрытые 128 примеров из 16 тематических групп, не видя ни одного обучающего или калибровочного текста. Калибровка выбрала один порог, максимизирующий убранные бытовые карточки без потери калибровочных сюжетов; модель и порог закреплены SHA-256 до открытия контроля. Совпадения ID, нормализованных запросов и объявленных семейств между наборами запрещены. Для всех трёх прогонов выходные данные источника не покидали локальную среду. Базовые карточки получены реальной E5 FP32, Linux x86-64 и теми же 50 реальными описаниями; строки тестов, веса, словарь и отпечатки не публикуются.

| Сравнение с неизменным поиском | Результат |
| --- | --- |
| Калибровка | 26 из 37 бытовых выдач сняты, 0 из 36 кинозапросов с выдачей потеряны |
| Независимые 64 бытовых / 64 кинозапроса | 30 из 59 бытовых выдач сняты (50,8%); 0 из 60 кинозапросов с выдачей потеряны; 0 из 30 коротких с выдачей потеряны |
| Последующая проверка тем же порогом на прежних 154 запечатанных запросах | Посторонние с карточками 24/30 → 16/30; Top-1 среди покрытых 14/36 → 13/36, Top-5 27/36 → 26/36; недостаточные детали 5/6 без изменения |

Пороги пилота на независимых синтетических примерах (точность среди снятых не ниже 95%, сократить не менее 35% прежних бытовых выдач, не снять ни одной короткой кино-выдачи) пройдены. Отдельный регрессионный предел допускал потерю не более одного Top-5; потеря ровно одного подтверждённого ответа означает, что делать жёсткий отказ по умолчанию преждевременно. Зафиксированный вариант не перенастраивается на этих результатах. Следующий обоснованный тест: обратимое уточнение с возможностью всё равно запустить поиск и независимая оценка на более широком круге задач. Это не измерение качества коммерческой версии, не доказательство результата на большом каталоге и не новый релиз.
