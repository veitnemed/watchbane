# WB-006. Карта сюжетного поиска Watchbane

Срез исходников: `1089cfb`. Ссылки рассчитаны на размещение файла в `docs/architecture/` репозитория.

| Контур | Реализация и границы |
|---|---|
| Старт | [`start_app.py`](../../start_app.py#L1) и [`preview.main`](../../preview.py#L10) настраивают локальный каталог и вызывают [`bootstrap.main`](../../desktop/shell/bootstrap.py#L146). Preview по умолчанию выбирает отдельный `.preview-profile`; `--check` проверяет заданные локальные данные/модель без окна. [`WatchedMoviesWindow`](../../desktop/shell/main_window.py#L49) собирает вкладки через [`build_main_tabs`](../../desktop/shell/tabs.py#L92), включая `StorySearchView` и коллекцию. Путь БД зависит от [активного профиля](../../storage/profiles.py#L78). |
| UI → поиск | [`StorySearchView.search`](../../desktop/story/view.py#L746) запускает [`StoryWorker.run`](../../desktop/story/view.py#L53) в **QThread того же процесса**: готовит каталог, выполняет `engine.search(query)`, отдаёт ответ/состояние через сигналы. Пока идёт работа, UI хранит один ожидающий запрос; см. [`_finished`](../../desktop/story/view.py#L787) и [`_show_results`](../../desktop/story/view.py#L802). Отмена проверяется при подготовке и перед поиском, но `engine.search` не получает токен этой отмены. Отдельного процесса QProcess для E5 в этом рабочем пути нет. |
| Локальные данные | [`story_catalog_snapshot`](../../candidates/story_service.py#L120) строит `StoryDocument` и отображение на исходные записи из **выбранного JSONL или** каталога SQLite профиля, не объединяя оба источника. [`resolve_catalog` / `load_seed_snapshot`](../../candidates/story_seed_snapshot.py#L19) выбирают/проверяют sidecar; он читается без импорта в SQLite. Пустой каталог не подменяется вымышленными историями. |
| Режимы и кэш | [`create_story_search`](../../candidates/story_service.py#L28) выбирает [`StorySearch.search`](../../candidates/story_search.py#L255) с локальным лексическим ретривером без заданной модели либо локальный ONNX [`LocalE5`](../../candidates/story_semantic.py#L18) и [`SemanticStorySearch.search`](../../candidates/story_semantic.py#L122) с гибридным ранжированием по умолчанию. Это два режима, не гарантия автоматического повтора в текстовом режиме при любой ошибке E5. Индекс и модель переиспользуются в памяти процесса; [`CachedPassageEncoder`](../../candidates/story_vector_cache.py#L90) сохраняет в профиле векторы описаний, а не запросов. |
| Импорт и внешние вызовы | [`_fill_catalog`](../../desktop/story/view.py#L456) по действию пользователя запускает импорт, [`fill_story_catalog`](../../candidates/story_catalog.py#L12) вызывает TMDb Discover/Details по фильтрам и типизированным ID, а не по тексту сюжета: до 15 на тип, до 10 страниц на тип, RU → EN при пустом RU. Запись пакета только после сбора, через [`import_story_catalog_candidates`](../../candidates/sources/tmdb/importer.py#L334) с `BEGIN IMMEDIATE`. Выбранный JSONL проверяет [`SnapshotCheckWorker`](../../desktop/story/view.py#L71), без модели и сети в этом шаге. |
| Модель, постеры и приватность | [`_start_model_install`](../../desktop/story/view.py#L625) запускает отдельный поток после явного действия; [`_open_artifact`](../../candidates/story_model_install.py#L94) проверяет URL, [`_download_set`](../../candidates/story_model_install.py#L156) сверяет файлы и контрольные суммы до подключения. [`CardPosters.bind`](../../desktop/shared/story_posters.py#L144) сначала пробует локальный постер, затем видимые карточки могут асинхронно обратиться к CDN TMDb; в таком запросе есть путь постера, не сюжетный запрос. Вывод модели и сопоставление сюжетов локальны; показ результатов сам по себе не означает полного отсутствия сетевого трафика. |
| Коллекция и транзакции | [`StorySearchView._act`](../../desktop/story/view.py#L917) передаёт исходную запись в сервис; [`_set_action_state`](../../candidates/title_state_service.py#L144) и [`mark_watched`](../../candidates/title_state_service.py#L220) согласуют статусы и запись в `BEGIN IMMEDIATE`. [`candidate_typed_state_key`](../../candidates/models/keys.py#L60) различает реальные фильм/сериал по типу и TMDb ID; legacy разрешается отдельно. SQLite использует [WAL, foreign keys и busy timeout](../../storage/sqlite/connection.py#L25). UI подтверждает сохранение после успешного результата, а не оптимистично. |
| Ошибки и восстановление | [`_snapshot_search_failed` / `_search_failed`](../../desktop/story/view.py#L776) отделяют ошибку файла каталога от общего сбоя поиска/модели; [коды установки](../../desktop/story/view.py#L102) различают контрольную сумму, простой соединения и общий лимит. [`ensure_sqlite_startup_migration`](../../storage/sqlite/startup.py#L210) и [`apply_migrations`](../../storage/sqlite/migrations.py#L157) ведут стартовую проверку и миграции. [`backup_sqlite_database`](../../storage/sqlite/backup.py#L43) использует SQLite backup с публикацией через временный файл; [`restore_sqlite_database`](../../storage/sqlite/backup.py#L111) валидирует источник, отдельно защищает восстановление существующей БД. [Диалог восстановления](../../desktop/shell/bootstrap.py#L29) не является сетевой операцией. |
